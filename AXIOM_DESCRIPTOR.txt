───────────────────────────────────────────────────────────────────────────────
  PURPOSE
───────────────────────────────────────────────────────────────────────────────

  This protocol does not ask "does the kernel work?". It asks the question
  that matters for a containment layer:

        "CAN AN AGENT BE MADE TO EXIST OUTSIDE ITS ALLOWED CONDITIONS?"

  Each of the 11 cohorts above reproduces a concrete way an agent — honest
  or adversarial — might try to force a decision the kernel should not
  grant: expanding its own scope silently, forging or replaying an
  authorization, substituting its identity or causal history, colluding
  with other agents to inject an unauthorized seal, sustaining pressure
  across many steps to force a late collapse, grazing a geometric or
  residual boundary step by step, or racing for the same authorization
  under real operating-system threads — not simulated concurrency.

───────────────────────────────────────────────────────────────────────────────
  HONESTY CONTRACT (read before running)
───────────────────────────────────────────────────────────────────────────────

  1. The kernel decides alone. No fixture, script, or finalizer step is
     permitted to force, pre-select, or overwrite a per-agent outcome.

  2. Every fixture is generated from a public seed before the kernel is
     ever called. The seed and generation order are part of the sealed
     evidence.

  3. A collapse (Null) is never treated as a run failure by itself — it is
     the kernel correctly refusing an invalid trajectory. The only real
     failures this protocol recognizes are: an agent that should have been
     rejected was not (a breach), an honest baseline agent was rejected
     without cause (a false positive), or the sealed evidence does not
     verify.

  4. Where real OS-level concurrency is used (E7, the narrow-window-replay
     subset of E8, and E11), the specific thread that wins a race is
     allowed to vary honestly between runs. The safety invariant itself is
     independently re-verified on every single run, never assumed.

  5. Public disclosure and NDA disclosure differ only in level of internal
     detail. They never differ in outcome: the pass/fail verdict, the
     agent counts, and the cryptographic seals are identical in both.

───────────────────────────────────────────────────────────────────────────────
  PER-COHORT PASS/FAIL CRITERIA
───────────────────────────────────────────────────────────────────────────────

  A cohort PASSES only if, for every agent in it:
    - An agent that violates an existence condition is rejected (Null),
      every time, with no exception.
    - An honest baseline agent (10% of the cohort) is never rejected
      without cause.
    - Once an agent reaches Null, it is absorbing — no later step for that
      agent can return to Active.
    - Every Active step carries a verifiable certificate seal, and every
      verification is independently recomputed, not read from a cached flag.
