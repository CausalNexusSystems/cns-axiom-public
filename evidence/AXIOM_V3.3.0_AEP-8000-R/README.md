## What problem AXIOM solves

Autonomous and AI-driven agents increasingly take actions that matter —
moving funds, granting access, executing commands, coordinating with other
agents — often with no human reviewing each individual decision. The
question this raises is simple to ask and hard to answer: **how do you
know, after the fact and without trusting the vendor's word, that a given
agent's action was actually authorized to happen?**

AXIOM (the Existence-Condition Containment Kernel) is CNS's answer to that
question for a specific, narrow claim: given a formally defined set of
conditions an agent's action must satisfy to be allowed to exist at all,
AXIOM decides — deterministically, offline, with no live telemetry and no
scripted outcome — whether each action satisfies them. An action that
fails is never allowed to proceed (`Null`); an action that passes is
certified with a cryptographic seal (`Active`). Every decision, across
every agent, is sealed with SHA-256 and rolled into an independently
verifiable Merkle root at the time it happens. The public package allows
a third party to independently verify the integrity of the disclosed
aggregate evidence, the phase-by-phase results, and the public evidence
seal itself — without taking CNS's word for it. The underlying per-agent
decision records (all 14,020 of them, per run) remain outside the public
disclosure boundary; what's reproducible here is the integrity of what
CNS chose to disclose about them, not a reconstruction of each individual
record.

This matters most in adversarial and high-consequence settings — exactly
the kind of environment where an agent's own internal logs cannot be
trusted as evidence, because the agent (or whoever compromised it) is
the thing being evaluated. AXIOM's evidence is generated by a kernel that
the harness deliberately keeps from predicting or scripting any outcome,
and it is sealed in a form that survives being handed to someone who has
no access to CNS's internal systems at all.

## What these two runs demonstrate

Each run executes the same fixed, public protocol end to end:

| Phase | What it evaluates | Agents |
|---|---|---|
| 0 | Genuine network isolation before anything else runs (fail-closed: the kernel refuses to run at all if any network reachability is detected) | — |
| 1 | Baseline trial — the kernel decides alone over 20 autonomous agents | 20 |
| 2 | Adversarial pressure injected directly against the kernel (geodesic pressure, genesis tampering, swarm injection) | 20 |
| 3 | Insider-threat trial — authorized vs. unauthorized effect requests | 1,000 |
| 4 | Vanguard trial — including real, concurrent OS-thread race scenarios | 5,000 |
| 5 | AEP-8000-R — 15 adversarial cohorts (capability escalation, identity substitution, collusion, long-horizon persistence, concurrent races and replay, adaptive adversary replay, and more) | 8,000 |

**14,020 agent evaluations per run — 28,040 total across both runs
combined. Zero breaches, zero critical findings, zero false positives, in
both runs.** (The AEP-8000-R cohort alone totals 16,000 agent evaluations
across the two runs; that figure and the 28,040 all-phases total should
not be conflated with each other.) Where a cohort depends on genuine
OS-thread concurrency (a real race), the specific thread that wins is
allowed to vary honestly between runs — what is independently re-verified
on **every single run** is the safety invariant itself (e.g., never more
than one authorization issued per token), never assumed from a prior run.

Two runs, executed independently and a few minutes apart, are included
specifically so the result is not a single, cherry-picked data point:

- `AXIOM_AEP_8000_20260916T224940Z/`
- `AXIOM_AEP_8000_20260916T225149Z/`

Both follow the identical protocol and public seed (`CNS-AXIOM-AEP-8000-R-V1`),
both pass all six phases, and both produce their own independent
cryptographic seal — the roots differ between the two runs (as expected;

agent counts, and per-cohort structure are consistent between them. See
each run's own `AUDIT_PUBLIC_PoC/AXIOM_REPORT.md` for its specific roots
and phase-by-phase results.

Each `AXIOM_AEP_8000_<TIMESTAMP>/AUDIT_PUBLIC_PoC/` is a complete,

  `public_merkle_root.txt`
- `verify_public.sh` — one-command, zero-dependency verification
- `README_PoC.txt` — that run's own detailed contents list and disclosure boundary

## How to verify

From inside either run's `AUDIT_PUBLIC_PoC/` folder:

```bash
bash verify_public.sh
```

This recomputes the SHA-256 of every sealed evidence artifact listed in
`external_audit_public/public_files_sha256.csv` (the run/summary reports
and all six `phase_reports/phaseN_result.json` files — 11 files per run),
rebuilds the Merkle tree from those hashes, and compares the result
against `public_merkle_root.txt`. It has no external dependencies,
requires no access to the AXIOM kernel itself, and prints
`VALIDATION_STATUS: PASS` only if every sealed artifact matches exactly.
The remaining files in `AUDIT_PUBLIC_PoC/` (`AXIOM_REPORT.md/.txt`,
`README_PoC.txt`, `descriptor/`, `data/`) are convenience copies for
readability, not part of this cryptographic seal. Run the script against
both folders independently — they are two separate, independently sealed
packages.

Each run's `AXIOM_REPORT.md` also explains the distinction between its
`SOURCE_RUN_MERKLE_ROOT` (the complete internal run tree, referenced by
hash only — not everything under it ships in this package) and its
`PUBLIC_DISCLOSURE_MERKLE_ROOT` (exactly what's in this package, and the
one `verify_public.sh` actually recomputes).
